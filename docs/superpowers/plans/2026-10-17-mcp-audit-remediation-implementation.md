## Review Focus

1. **Evidence can become more complete but less accurate.** Country scope must include all 69 budgets while territorial rows exclude the five aggregate-only budgets, and named documents must match the year. Tasks 2–3 verify exact IDs, roles and periods while preserving arithmetic.
2. **An outer catch does not cover errors caught by the SDK.** Callback, persistent shaping faults, missing structured output and actual late validation must all be tested in both protocol eras. Prepare the safe fallback before callbacks run so the catch cannot re-enter the broken formatter. Task 4 owns these assertions; Tasks 5 and 12 repeat affected compatibility proof after changes.
3. **Discovery and caches can silently mislead.** City choices must be queryable; caches must distinguish snapshots/bases without changing missingness or exposing shared mutation. Tasks 6–7 verify semantics, first-query cache-fill cost and memory under distinct valid keys as well as warmed speed.
4. **A new review date can hide a data regression or cause an expected test mismatch.** Separate numeric/identity changes from review metadata, respect product source readiness, and explicitly review the two release-sensitive reference coverage endpoints before activating a new vintage. Tasks 8–9 and 12 own this boundary.
5. **Verification can fail for setup reasons or prove too little.** Enable/configure MCP only in the dedicated local server process, then execute all 14 tools in the release probe. SDK success is not real-app acceptance; a deploy hook is not a live release; a smoke report is not retained production logs. Tasks 10–13 keep these proofs separate.
