# U19-living-income-spending: Living standards, Income and Spending (index + Georgia/region pages)

Pages reviewed (live build, localhost:3100): `/explorer/living-standards/income`, `/spending`, `/income/regions/georgia`, `/income/regions/kakheti`, `/spending/regions/georgia`, `/spending/regions/tbilisi`, and the `/en/…` mirrors. Files: `apps/web/lib/pages/household.tsx`, `apps/web/components/household/household-explorer.tsx`, `apps/web/lib/explorer/household*.ts`.

## Summary

The unit is well built: no overflow at 375px, no console errors, safe hash parsing, correct canonical/hreflang/JSON-LD/sitemap, KA and EN carry identical controls (same `data-testid` set), and the existing browser spec (13 tests) and unit tests (45) all pass.
The one real gap is on phones: the area pages never mount `ChartSelectionAids`, so there is no phone legend and no return-to-chart pill, which DESIGN.md requires and which Poverty/Wages/Trade already have. Second is bundle waste: the index pages ship the whole chart/table/picker/Excel client code they never use, and the area pages inline ~100-byte-per-row fact JSON.
Scores (1-10): code quality 7, performance 6, UI/UX 7, mobile 5, accessibility 7, bilingual 8, SEO 8, security 9, tests 7.

## Not checked (and why)

- Correctness of any numbers (out of scope).
- Colour contrast ratios by tool (no axe available offline); only visual review of screenshots at 375 and 1280.
- Screen-reader behaviour (no AT here); roles/labels read from the DOM only.
- Excel file contents beyond reading `householdWorkbook.ts` and the existing unit tests (no leaked internal columns in the code: only year, label, amount, status and validated source links).
- The shared baseline JS (14 chunks, 757 KB raw / 232 KB gz, identical on the hub, index and area pages) is shell/layout cost owned by other units.
- Real touch devices; touch-preview strip was checked with Playwright touch emulation on the index (first tap previews `იმერეთი · 2,061.2 ₾ →`, second tap navigates) and works.
- Verified and not a problem: no horizontal overflow at 375 (scrollWidth 375), no console or page errors, hash input (`<img onerror>`, `../../etc`, reversed or huge ranges, empty `sel=`) is parsed safely with sane fallbacks and the empty selection shows the callout; no `dangerouslySetInnerHTML`; the only external link (geoBoundaries) has `rel="noreferrer"`; canonical, hreflang (ka, en, x-default), og tags, Dataset + Breadcrumb JSON-LD present and correct for ka and en; all 24 area pages and both indexes are in `sitemap.xml`; KA/EN have identical `data-testid` sets; caret buttons on rows without children are `visibility:hidden; tabindex=-1` so they do not count as small tap targets; Dataset `@id` being locale-independent is the site-wide pattern.
