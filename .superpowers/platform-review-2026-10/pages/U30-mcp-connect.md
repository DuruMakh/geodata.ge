# U30-mcp-connect review (`/mcp`, `/connect`, `/en/connect`)

## Summary
The endpoint is well guarded: Host/Origin checks, body cap, fail-closed limiter, bilingual error envelope and a clean `/connect` page all behaved as designed. The costs are performance: every request rebuilds the tool server (63 ms for a `ping`), the packaged snapshot is 46 MB, and `tools/list` is 119 KB.
Scores (1-10): code quality 7, performance 5, UI/UX 8, mobile 8, accessibility 7, bilingual 8, SEO 9, security 8, tests 6.
Note: the local build on :3100 has `MCP_ENABLED` unset, so `/mcp` there answers 503 to every POST (by design, and GET still 405). I drove the real `app/mcp/route.ts` handler in-process with `tsx` (`MCP_ENABLED=true MCP_RATE_LIMITER=memory NEXT_PUBLIC_SITE_URL=https://fiscal.ge`). I also sent one `ping` to production https://fiscal.ge/mcp: 200, so production is enabled.

Measured, no limiter configured: with `MCP_ENABLED=true` and no `MCP_RATE_LIMITER`/Upstash vars, every POST returns 503 `service_unavailable` ("Request limiting is unavailable", `retry-after: 60`), bilingual body. With `MCP_RATE_LIMITER=memory`, request 61 within a minute from one key returns 429 `retry-after: 60`; a second key is unaffected. `VERCEL_ENV=production` refuses the memory counter (code read, and covered by tests).

Other measured behaviour (all as designed): GET and DELETE 405 `allow: POST`; malformed JSON 400 code -32700; batch 400 -32600; empty body 400; wrong Host 403 `forbidden_host`; bad Origin 403 `forbidden_origin`; 200 KB body 413; 32 KiB+ body 413; wrong Accept 406; wrong Content-Type 415; unknown tool JSON-RPC -32602; preflight from an unapproved origin 403, from an approved origin 204 with the exact origin echoed; `cache-control: no-store` and `vary: origin` everywhere.

HTML: `/connect` 108,867 B raw / 20,835 B gzip; `/en/connect` 78,803 raw / 17,596 gzip. JS referenced: 9 chunks, 597,123 B raw / 184,955 B gzip, identical on `/about` (596,065 / 184,589), so it is the shared shell. Sitemap, canonical, hreflang pair, x-default, JSON-LD (Organization, WebSite, BreadcrumbList), `lang`, meta and OG all correct for both locales. External doc links return 200.

## Not checked (and why)
- Live production behaviour beyond one `ping` (rate limiting with real Upstash, daily cap, real `VERCEL_ENV`): requires production env vars and would mean sending volume; only in-process memory-counter and fail-closed behaviour were measured.
- Whether claude.ai / ChatGPT connectors share egress IPs (finding 04): cannot be observed from this sandbox.
- Numbers returned by tools (out of scope as instructed); `lib/factQuery/*` query modules were sampled through their tool outputs, not read line by line (about 10,000 lines).
- Excel/workbook content and internal metadata columns: this unit has no workbook export; checked HTML/RSC only (no `dangerouslySetInnerHTML` except 4 JSON-LD scripts, no `target=_blank`, no URL hash/query parsing on `/connect`; `?x=<script>` is not reflected).
- Screen-reader announcement quality (only the live region markup and keyboard order were checked); colour contrast measured for muted text (rgb 106,96,80 on 247,242,233, about 5.5:1) and body, not the full page.
- The Playwright connect spec was run once against :3100 (10 passed, 7.1 s); no tracked files changed (`git status` clean).
