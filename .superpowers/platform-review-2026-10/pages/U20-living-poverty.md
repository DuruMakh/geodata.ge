# U20-living-poverty review (`/explorer/living-standards/poverty`, `/explorer/living-standards/inequality`, ka + en)

## Summary
Page is in good shape: no overflow at 375px, correct canonical/hreflang/JSON-LD/sitemap, bilingual parity, keyboard path works, Excel value column has the right number format (checked in real downloads). Main weak spots are copy-paste duplication with the Household/Wages/MoneyBanks/Unemployment siblings, a 22px expand caret that fails WCAG 2.2 target size (axe "serious"), a lead line that does not follow the tab, and no page-level SEO/metadata test.
Scores (1-10): code quality 6, performance 7, UI/UX 7, mobile 8, accessibility 7, bilingual 8, SEO 8, security 9, tests 6.
Measured: HTML ka poverty 167,905 B raw / 21,340 gz; en poverty 141,822 / 19,317; ka inequality 131,437 / 19,069; en inequality 105,416 / 17,065. JS referenced: 14 files, 738,548 B raw / 226,312 gz (of which 112,594 raw / 39,627 gz is the `noModule` legacy polyfill chunk 0cz1d0mv5g_q7.js; modern browsers load about 626 KB raw / 187 KB gz; exceljs is lazy-loaded on click). Page-specific chunks (the 7 listed for PovertyExplorer) = 171 KB raw. Same chunk set for all four pages.

## Not checked (and why)
- Whether the numbers are correct (out of scope).
- Safari/Firefox rendering; real screen reader (NVDA/VoiceOver) behaviour. Only axe-core (wcag2a/aa/21aa/22aa + best-practice) at 1280 and 375 on 4 pages/states, a 30-step Tab sequence (focus ring is a 2px solid outline everywhere), and screenshots in Chromium were done.
- Chart pointer/tap tooltip interaction (shared `EditorialLineChart`, covered by other units).
- Hub card page `/explorer/living-standards` (belongs to another unit).
- `useHashState` internals (shared); URL hash on this page only maps through `parsePovertyHash`, which keeps only known series ids and a validated tab/range, so no user text reaches the DOM; no `dangerouslySetInnerHTML` except JSON-LD built from fixed data.
- Chart DOM: both desktop and mobile SVGs are rendered in the HTML (two sets of axis ticks in SSR output, `data-geometry` desktop/mobile) and one is hidden by CSS; this is the shared chart's design, noted but not measured for cost.
