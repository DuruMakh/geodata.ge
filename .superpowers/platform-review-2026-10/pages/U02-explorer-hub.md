## Summary

Unit U02-explorer-hub (`/explorer`, `/en/explorer`), reviewed read-only against the live build on :3100. SEO/metadata, bilingual parity, security and 375px layout are sound; the problems are the hub lead paragraph breaking DESIGN.md §17, sidebar accessibility and copy-paste bloat, and a few brittle or redundant tests.
Scores (1-10): code quality 5, performance 7, UI/UX 6, mobile 7, accessibility 5, bilingual 9, SEO 9, security 10, tests 6.
Counts: 0 critical, 0 high, 6 medium, 9 low.

Measured facts used below: KA HTML 82,197 B raw / 13,920 B gzip; EN 66,666 / 12,294. JS (12 chunks the page references, noModule polyfill excluded) 557,800 B raw / 164,038 B gzip; /methodology is 484,025 / 145,312, so the hub-specific part is about +74 KB raw. Inline RSC flight data is 39 KB of the KA HTML. CSS 76,105 / 14,716 gzip. 375px: no horizontal overflow in KA or EN, no console errors.

## Not checked (and why)

- Whether any numbers are correct (out of scope).
- Full browser-suite runtime and flakiness: only the hub/sidebar specs listed above were run (each passed, single worker). The default Playwright launch failed on this machine (no headless-shell binary), so I ran them with a temp config pointing at `/opt/pw-browsers/chromium-1194` (config is in /tmp, nothing in the repo changed).
- What exactly sits inside the two big framework chunks (228 KB and 156 KB raw): bundle contents are minified; I only confirmed they hold the React/Next runtime and not app libraries (no d3, xlsx, three, etc. found by string search).
- Chart render cost and legends: the hub has no charts, only six decorative 200x34 SVG sparklines (7 SVGs, 3.2 KB total).
- Real screen-reader output and Windows high-contrast mode: only DOM/attribute inspection.
- Collapsed-rail (900px+) state and `localStorage` persistence: covered by existing passing tests, not re-examined.
- `rel`/`noopener` on external links: the hub has none (only `mailto:`); `dangerouslySetInnerHTML` appears only in Next's own error-page payload. `LegacyHashRedirect` only accepts `expenditure|revenue|analysis` (`lib/explorer/urlState.ts:178-185`), so the hash cannot inject a destination.
