# U11-economy-sectors — `/explorer/economy/sectors` (ka) and `/en/explorer/economy/sectors`

## Summary
The page is in good shape: no security issues, clean SEO pair, no horizontal overflow at 375px, 33 browser tests and 28 unit tests pass against the live build.
The real problems are small: a flat 100% chart and a tautological headline in the share-of-GDP measure, a generic chart label for screen readers, about 105 KB of repeated fact JSON in every HTML, and a test suite that repeats itself.
Scores (1-10): code quality 7, performance 7, UI/UX 7, mobile 8, accessibility 7, bilingual 9, SEO 9, security 10, tests 6.

## Not checked (and why)
- Number correctness (out of scope by brief).
- The two lines under the heading (latest-value line plus the measure description): DESIGN.md line 1095 asks for "concise explanations under the heading" for sectors, and §17 says other existing pages stay unchanged until the owner asks, so I treated it as a decision, not a finding.
- Excel contents beyond `economicSectorsWorkbook.ts` and its tests: I read the builder (no internal metadata columns; sources use public `/downloads/methodology/...` hrefs). I did not open a generated file.
- The `/downloads/data/economic-sectors.csv` publication (303 KB, 200 OK, has `source_id` and `series_id` columns by design) was only fetched, not reviewed.
- Colour contrast measured by tool: not run; palette contrast is enforced by `economicSectors.test.ts`.
- Screen-reader and real-device testing: not available here; findings are from DOM inspection and a headless Chromium at 375px.
- JS weight: 14 chunks, 751,672 B raw / 229,934 B gzip, identical for ka and en; the economy hub loads 203,109 B gzip and wages 233,220 B, so the sector page adds little on top of the shared baseline. Excel writer is loaded lazily.
