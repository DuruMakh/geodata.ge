# U06-debt: /explorer/debt (ka) and /en/explorer/debt

Reviewed against the live build at http://localhost:3100 (desktop 1440, phone 375, Chromium). Files: `apps/web/lib/pages/debt.tsx`, `apps/web/components/debt/*`.

## Summary

Solid page: one H1, one lead line, no overflow at 375px, correct metadata/hreflang/JSON-LD/sitemap, no unsafe HTML, hash input is sanitised, 54 debt unit tests and 19 debt browser tests pass. Real problems are shared-chart accessibility (no keyboard readout), unmarked forecast values in the legend/tooltip, and the debt hash hook not following `hashchange`.
Scores (1-10): code quality 7, performance 8, UI/UX 8, mobile 8, accessibility 6, bilingual 8, SEO 8, security 9, tests 7.
Measured: HTML 151,399 B raw / 20,862 B gzip (ka), 125,015 / 19,007 (en). JS for the route: 14 chunks, 753,287 B raw / 231,675 B gzip (deficit 746,979 / 229,671; /about 596,065 / 184,589), so nothing debt-specific is out of line. Inline RSC payload about 29 KB raw (126 facts, 30 GDP years, source lists).

## Not checked (and why)

- Numerical correctness of facts, GDP shares, workbook values (out of scope per brief).
- Screen-reader behaviour with a real AT (only DOM roles/names and Tab order were inspected; focus ring is visible on all 22 tab stops, 2px accent, except the measure pill which uses a 2px muted ring).
- Full-suite runs: only debt-related specs/tests were run (debt.spec 9/9, bilingual-debt-deficit 10/10, main-explorer "Debt Excel", mobile-repairs-pages forecast-marker, six debt unit files); not the generic sweeps (mobile-fit-charts, mobile-repairs-charts, mobile-repairs-tables), whose runtimes were not measured.
- Real-device touch behaviour (tap-to-pin tooltip): only emulated.
- Production Vercel deployment and headers (only localhost:3100 was available).
