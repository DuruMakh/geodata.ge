# X3 build, CI and tests

Measured 2026-10-12 on a 4-core Linux box while 10 to 30 other review agents were running vitest and Playwright. Load average was 12 to 18 for most of the unit run and the browser sample, so absolute times are inflated about 3 to 4 times. Ratios and counts are the reliable numbers. Unloaded figures: build log `/tmp/claude-0/build.log` (load about 1) and `data:check-fact-query-snapshot`, re-timed at load 0.8 (7.3 s).

## Summary
The suites grew faster than the infrastructure. The browser suite has 1403 tests (281 on 2026-09-06), and CI runs it at 1 worker after building the site a second time. The same fact-query snapshot is rebuilt at least 5 times per check plus build, and again in 48 unit files. The biggest wins are infrastructure: one build per CI run, caches, shared fixtures. Pruning individual tests matters less.
Scores: build 5/10 · CI 4/10 · unit suite 5/10 · browser suite 4/10 · redundancy 4/10 · flakiness 6/10 · gate composition 5/10.

### Gate composition (area 7)
`npm run check` = lint → typecheck → (`pretest`: snapshot write) → vitest → `data:validate` (30 scripts, including a snapshot `--check` and the methodology archive `--check`) → `i18n:check`. `npm run build` = prebuild (archives write, **i18n:check again**, public datasets, snapshot write, regional/inflation public CSVs, publications, which **rebuild the snapshot**) → `next build` (**TypeScript again**, 45 s) → postbuild (4 re-checks of what prebuild wrote + function size). CI `checks` runs all of these once, then `e2e` repeats the whole build (-01).
Build time breakdown (`build.log`, 262 s real, 474 s user): compile 38.3 s, TypeScript 45 s, static generation 81 s (589 pages, 3 workers), and about 98 s of prebuild, page-data collection, finalize and postbuild combined. The log has no per-step timestamps. Of that 98 s, the archive hashing (55.7 s and 42 s for the archive and publication checks under load, about 15 s and 12 s unloaded) and the double snapshot are the identifiable bulk. Realistic savings: -05 about 30 to 45 s, -06 about 45 s, -04(a) about 6 s, -03 a share of the 38 s compile on warm cache. That is roughly 25 to 35 % off each build, doubled in CI by -01.

`pretest` cost: one full snapshot build, 7.3 s for the equivalent `--check` at load 0.8 (CLAUDE.md: 4 s). It is paid by every `npm test`, including single-file reruns through npm.

**Shared fixture (one):** `tests/helpers/factQuerySnapshot.ts` exporting `testSnapshot(overrides?)`. It reads `lib/factQuery/generated/snapshot.json`, which `pretest` already writes, or, if that is absent, builds once in a vitest `globalSetup` that writes the file and `provide()`s its path. It returns the parsed object with `releaseCommit` and `generatedAt` replaced; `BuildSnapshotOptions` has only those two fields (`lib/factQuery/buildSnapshot.ts:41`). Replace the `beforeAll(buildFactQuerySnapshot(...))` in the 45 files that build with options only. `pool: "forks"` isolates modules per file, so the sharing has to go through the file, not a module-level memo. Expected saving: about 180 of the 216 s summed (each file pays a JSON parse of about 0.3 s instead of a build).
