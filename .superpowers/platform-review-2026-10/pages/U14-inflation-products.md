# U14-inflation-products — `/explorer/inflation/products` (ka) and `/en/explorer/inflation/products`

Reviewed against the live build on :3100 (Chromium 1243, Playwright) on 2026-10-12. Read-only; throwaway scripts in `/tmp/review-U14-inflation-products/`.

## Summary
The page works and its structure is sound: the heading and lead line, the selection rules, the icon-only toggle, the hash state, the Excel export and the ka/en parity all hold, and all 11 browser tests and 28 related unit tests pass. The weaknesses are weight and responsiveness (1.46 MB HTML of which 680 KB is inline data, 305 SSR panel rows, 94-180 ms per selection) plus two real UX defects: line colours repeat across selected products, and the 305-row selector costs 308 Tab presses to pass.
Scores (1-10): code quality 6, performance 4, UI/UX and design 7, mobile 8, accessibility 6, bilingual 9, SEO 8, security 9, tests 7.

## Not checked (and why)
- Numerical correctness of rates and cumulative values (out of scope per the brief).
- Real-device phone performance and a throttled-CPU INP: only the desktop-class sandbox CPU was available, so the 4-6x phone multiplier in -03 is an estimate.
- Full screen-reader run (NVDA/VoiceOver): checked markup, names, roles and tab order only.
- Colour contrast of every token: only inspected visually in screenshots; no contrast tool run.
- Root cause of the 0.124 mobile layout shift (-15): the shifting nodes were identified, the cause in the shared header was not isolated.
- Behaviour when JavaScript fails or a shared hash holds hostile input beyond the `URLSearchParams` path: read the code (`inflationProductState.ts`, ids filtered through `index.productById`, years via `\d{4}` regex and clamped, no `dangerouslySetInnerHTML`, no external links on this unit); no fuzzing run.
- Production network headers and CDN caching for `/inflation-products/*.webp` (the local server was used).
