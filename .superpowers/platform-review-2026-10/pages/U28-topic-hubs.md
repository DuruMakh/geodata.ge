# U28-topic-hubs review

Scope: the ten topic hubs (`/explorer/{economy,inflation,unemployment,wages,trade,external,money,energy-food,living-standards,demography}`, ka and `/en`). Live build at http://localhost:3100 (canonical host https://fiscal.ge). Measured with curl, a throwaway Playwright script at 375 and 1280 px, one Playwright run and two vitest runs. `git status` was clean after every run.

## Summary
- Scores (1-10): code quality 5, performance 5, UI/UX 6, mobile 8, accessibility 7, bilingual 7, SEO 5, security 9, tests 6.
- Biggest problems: seven hubs download explorer chart code they never render (+22 to +70 KB gzip of JS). The Economy hub has no BreadcrumbList JSON-LD. Ten hand-copied page skeletons have already drifted apart (wrapper classes, empty coverage label, lead-line length). Energy and food cards show bare numbers with no unit.
- Security is clean: no hub reads URL input except `UnemploymentLegacyLink`, which can only redirect to a fixed registry of section paths. There is no `dangerouslySetInnerHTML`, no external link and no internal id in the hub HTML.

- No check that the sitemap `lastmod` of a hub covers every dataset the hub reads (finding 13).

## Not checked (and why)
- Numerical correctness of card figures and sparklines (out of scope by brief).
- Screen-reader announcements and real assistive-technology behaviour (only DOM, tab order and computed styles were checked).
- Sparkline colour contrast (computed from tokens only by the existing `color-contrast.ts`; not re-measured).
- `/en` bundles beyond trade/inflation/economy/living-standards: JS chunk lists are identical for ka and en, so the ka numbers were used.
- Full Playwright and vitest suites (single files only, per brief): ran `wages.spec.ts -g hub`, `money-banks.spec.ts -g hub`, `unemployment.spec.ts -g "four unemployment cards"`, the six hub unit files (28 tests, 6.1 s) and `shellClasses.test.tsx` (11 tests, 11.7 s). All passed; no tracked files changed.
- Child pages of the hubs (explorer workspaces) belong to other units; finding 14 touches them only because the code sits in the same files.
