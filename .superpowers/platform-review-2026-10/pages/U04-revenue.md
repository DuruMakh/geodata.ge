# U04-revenue — `/explorer/revenue` (KA) and `/en/explorer/revenue` (EN)

Reviewed against the live build at http://localhost:3100 on 2026-10-12. Read-only. Scratch scripts are in /tmp/review-U04-revenue/.

## Summary

Solid page: axe-core reports 0 violations at 1280px and 375px (KA and EN), no page overflow at 375px, no console errors, a clean Excel export, whitelisted URL-hash parsing, complete hreflang/canonical/JSON-LD/sitemap. Problems are mostly in the shared template (chart keyboard/legend/label truncation, one over-wide client bundle) and in revenue-specific data presentation (a −10 axis floor, 0.1-bn rounding of small receipts).
Scores (1-10): code quality 6, performance 7, UI/UX 7, mobile 8, accessibility 6, bilingual 8, SEO 8, security 9, tests 6.
Counts: critical 0, high 0, medium 3, low 11.

Measured: HTML 192,263 B raw / 25,944 B gzip (KA), 161,838 / 24,001 (EN). The inline RSC payload is 83.5 KB raw of that. First-load JS is 15 scripts, 808,998 B raw / 245,803 B gzip; /about alone is 184,589 B gzip, so this route adds about 61 KB gzip.

- Whether the numbers are correct: out of scope per the brief.
- The ministries/analysis scopes and the `/explorer/analysis` route: not reachable from this route (they belong to U03/analysis units).
- A real screen reader (NVDA/VoiceOver) and real touch hardware: only automated axe-core, a Playwright keyboard run and an emulated 375px touch context were available.

- Response headers beyond HTTP 200 / `Cache-Control: s-maxage=31536000`: caching and CDN behaviour belong to deployment.
- The full Playwright suite and `npm run check` (not allowed by the brief); only the revenue-related specs listed above were run, with a throwaway config in /tmp that points at the pre-installed Chromium (all 21 runs passed).
