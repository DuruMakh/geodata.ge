# U10-gdp review: /explorer/economy/gdp (ka) and /en/explorer/economy/gdp

## Summary
Page is sound: axe-core (wcag2a/aa/21aa/22aa + best-practice) reports 0 violations in ka/en, 1280 and 375 px, in line, table, growth and per-capita states. No horizontal overflow at 375 px, hash parsing is whitelisted, no unsafe HTML, SEO block complete. The defects are small: a non-localized, tooltip-less currency toggle, a generic chart accessible name, a double-line header block, and a source-list mapping hack that emits duplicate source ids.
Scores (1-10): code quality 6, performance 7, UI/UX 7, mobile 8, accessibility 7, bilingual 8, SEO 9, security 10, tests 6.
Measured: HTML ka 173,074 B raw / 29,912 B gzip, en 125,379 B / 25,359 B; JS 14 chunks 737,726 B raw / 226,276 B gzip (same for ka/en; exceljs is lazy-loaded). Peers: /explorer/economy hub 203 KB gz, /explorer/wages 233 KB gz, /explorer/economy/sectors 230 KB gz, so GDP adds little over the shared shell. tests: tests/browser/gdp-overview.spec.ts 15 passed in 17.4 s; 4 related vitest files (15 tests) pass in 2.7 s.

## Not checked (and why)

- Excel workbook contents in a browser download (only code and unit tests read; bilingual-workbooks.spec.ts covers the download).
- Colour contrast beyond axe-core's automated rules; no pixel-level review of the desktop layout beyond screenshots at 375 px.
- Lighthouse/LCP timings and chart render cost: measured only DOM size (34 SVG nodes, 18 text nodes, 334 DOM nodes total at 1280 px), not frame times.
- Hover/touch pin behaviour of the chart tooltip (shared component, covered by other units).
